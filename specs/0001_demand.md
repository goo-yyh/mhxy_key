# 轻量级鼠标键盘按键模拟程序需求文档

- 文档编号：0001

- 应用名称：无敌小铃铛
- Bundle Identifier：`com.yuyuehui.mhxykey`

- 目标平台：macOS、Windows
- 技术栈要求：Tauri + React + Ant Design

## 1. 背景与目标

开发一个轻量级桌面程序，用于配置全局快捷键触发一组键盘、鼠标模拟操作。程序需要支持多个配置项，每个配置项可以独立启用、停用，也可以通过专属快捷键切换启用状态。程序需要在 macOS 和 Windows 上运行，Windows 安装包需要通过 GitHub Actions 打包产出。

核心目标：

1. 让用户可以快速创建“触发快捷键 -> 执行动作序列”的自动化配置。
2. 让用户可以通过主界面、托盘菜单、配置快捷键控制配置启停。
3. 确保程序退出前停止所有运行中的配置和全局监听，避免残留按键或后台逻辑。
4. 配置本地持久化，重新打开程序后恢复上次保存的配置并按保存状态生效。

1. Tauri 桌面应用。
2. Ant Design 实现简洁配置页面。

9. 支持托盘右键菜单切换全局开关、切换每个配置、退出程序。
10. 支持关闭窗口时停止所有配置并退出程序。
11. 支持本地配置保存、启动恢复、导入和导出。

## 3. 术语定义

| 术语 | 说明 |
| --- | --- |
| 配置 | 一个自动化规则，包含触发快捷键、启停快捷键、动作序列、启用状态等信息。 |
| 触发快捷键 | 用户按下后执行动作序列的全局快捷键。 |
| 启停快捷键 | 用户按下后切换单个配置启用或停用状态的全局快捷键。 |
| 全局启停快捷键 | 用户按下后切换全局总开关开启或关闭状态的全局快捷键。 |
| 动作序列 | 被触发后按顺序执行的一组键盘或鼠标模拟动作。 |
| 全局总开关 | 控制所有配置是否处于可运行状态的总开关。 |
| 运行态关闭 | 注销全局快捷键、停止监听和任务，不代表把配置文件中的启用状态改成关闭。 |

## 4. 默认约定

1. 触发快捷键仅支持键盘组合键，不在界面中提供鼠标按键作为触发项。
2. 明确禁止鼠标左键和鼠标右键作为触发项。
3. 鼠标左键、右键、中键允许作为模拟动作。
4. 鼠标点击动作默认点击当前鼠标所在位置，不支持固定坐标配置。
5. 本期支持鼠标单击和双击，不支持鼠标移动和滚轮动作。
6. 不支持开机自启动。
7. 配置支持导入、导出，但不需要跨平台自动共享同一份配置文件。
8. 每个配置的启用状态会被保存。
9. 程序退出前必须运行态关闭所有配置，但不修改用户保存的启用状态；再次打开时，配置按保存状态恢复。
10. 全局总开关默认保存；如果上次退出前总开关为开启，则下次启动后自动注册已启用配置。
11. 当全局总开关关闭时，所有触发快捷键暂停生效；配置的启停快捷键仍可用于调整单个配置的保存状态。
12. 如果某个快捷键注册失败，需要在界面展示错误状态，并不影响其他配置继续运行。

## 5. 功能需求

### 5.1 主界面

主界面需要保持简洁，建议使用单页布局：

1. 顶部区域：
   - 应用名称：无敌小铃铛。
   - 全局总开关。
   - 全局启停快捷键设置入口。
   - 当前启用配置数量。
   - 新建配置按钮。
   - 导入配置按钮。
   - 导出配置按钮。
2. 配置列表区域：
   - 配置名称。
   - 触发快捷键。
   - 启停快捷键。
   - 动作摘要。
   - 当前状态。
   - 启用/停用开关。
   - 编辑按钮。
   - 删除按钮。
3. 空状态：
   - 当没有配置时，展示一个清晰的新建入口。
4. 错误状态：
   - 当快捷键冲突、注册失败、权限不足时，在配置行展示简短错误提示。

### 5.2 配置管理

用户可以创建、编辑、删除配置。

配置字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 是 | 程序生成的唯一标识。 |
| name | 是 | 配置名称，不能为空。 |
| enabled | 是 | 单个配置是否启用。 |
| triggerHotkey | 是 | 触发动作序列的全局快捷键。 |
| toggleHotkey | 否 | 切换该配置启用/停用的全局快捷键。 |
| actions | 是 | 至少一个模拟动作。 |
| createdAt | 是 | 创建时间。 |
| updatedAt | 是 | 更新时间。 |

配置校验：

1. 配置名称不能为空。
2. 触发快捷键不能为空。
3. 触发快捷键不能是鼠标左键或鼠标右键。
4. 动作序列不能为空。
5. 同一平台内，已启用配置的触发快捷键不能重复。
6. 同一平台内，启停快捷键不能与其他启停快捷键重复。
7. 同一配置内，触发快捷键不能与启停快捷键相同。
8. 全局启停快捷键不能与任何配置的触发快捷键、启停快捷键冲突。
9. 删除配置前需要二次确认。

### 5.3 全局总开关

全局总开关用于一键控制所有配置的运行态：

1. 开启时：
   - 注册所有 `enabled = true` 的配置触发快捷键。
   - 注册所有配置的启停快捷键。
   - 如果某个配置注册失败，仅该配置进入错误状态。
2. 关闭时：
   - 注销所有配置的触发快捷键。
   - 停止所有等待执行或正在排队的动作。
   - 释放可能残留的按键或鼠标状态。
   - 配置的 `enabled` 字段保持不变。
3. 总开关状态需要持久化。
4. 用户可以配置一个可选的全局启停快捷键。
5. 按下全局启停快捷键后，切换全局总开关状态。
6. 全局启停快捷键不能与任何配置的触发快捷键、启停快捷键冲突。

### 5.4 单个配置启停

每个配置都可以单独开启或关闭：

1. 用户可以在主界面配置行切换。
2. 用户可以在托盘菜单切换。
3. 用户可以通过该配置的启停快捷键切换。
4. 关闭单个配置时：
   - 注销该配置触发快捷键。
   - 如果该配置正在执行动作，本次执行应停止或尽快中断。
   - 保存最新启用状态。
5. 开启单个配置时：
   - 如果全局总开关开启，立即注册触发快捷键。
   - 如果全局总开关关闭，仅保存启用状态，不立即生效。

### 5.5 触发快捷键

触发快捷键用于执行动作序列。

要求：

1. 支持键盘组合键，例如：
   - macOS：`Option + A`、`Command + A`、`Control + Shift + 1`。
   - Windows：`Alt + A`、`Ctrl + A`、`Ctrl + Shift + 1`。
2. 快捷键录入时使用“捕获快捷键”交互，用户按下组合键后自动填入。
3. 必须至少包含一个普通键。
4. 禁止鼠标左键、鼠标右键作为触发项。
5. 按住快捷键时不能无限重复触发，需要做防抖。
6. 默认防抖时间：300 ms。

### 5.6 启停快捷键

每个配置可以设置一个可选的启停快捷键。

要求：

1. 按下启停快捷键后，切换该配置 `enabled` 状态。
2. 启停快捷键不执行动作序列。
3. 启停快捷键需要在全局总开关开启时注册。
4. 当全局总开关关闭时，启停快捷键仍建议保持可用，用于修改配置状态；如果底层库限制无法做到，需要在实现文档中说明。
5. 启停快捷键与触发快捷键、其他启停快捷键冲突时，需要提示用户修改。

### 5.7 动作序列

每个配置需要支持一个或多个动作，触发后按顺序执行。

动作类型：

| 动作类型 | 说明 | 示例 |
| --- | --- | --- |
| 键盘组合键 | 模拟按下并释放一组键盘组合键。 | `Command + A`、`Option + A`、`Ctrl + C` |
| 鼠标点击 | 模拟鼠标点击当前位置。 | 左键单击、左键双击、右键单击、中键单击 |
| 等待 | 等待指定毫秒数后继续下一步。 | 等待 100 ms |

动作字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| type | 是 | `keyCombo`、`mouseClick`、`delay`。 |
| keys | 条件必填 | `keyCombo` 动作需要填写。 |
| button | 条件必填 | `mouseClick` 动作需要填写。 |
| clickCount | 否 | 点击次数，默认 1；本期支持 1 或 2。 |
| durationMs | 条件必填 | `delay` 动作需要填写。 |
| delayAfterMs | 否 | 当前动作完成后的等待时间，默认 0。 |

执行示例：

1. 触发快捷键：`Command + A`
2. 动作序列：
   - 执行 `Option + A`
   - 等待 `100 ms`
   - 执行鼠标左键单击

### 5.8 执行控制

动作执行需要稳定、可控：

1. 同一配置正在执行时，再次触发默认忽略。
2. 全局动作执行建议使用串行队列，避免多个配置同时模拟输入造成错乱。
3. 动作执行期间，应尽量避免模拟出来的按键再次触发其他配置。
4. 如果无法可靠区分真实输入和模拟输入，动作执行期间应临时暂停触发监听。
5. 全局总开关关闭、单个配置关闭、程序退出时，需要取消未执行的动作。
6. 程序异常捕获到错误时，需要释放所有可能按住的按键。

### 5.9 托盘行为

窗口与托盘行为：

1. 点击最小化：
   - 主窗口隐藏。
   - 程序继续在托盘运行。
   - 已启用配置继续生效。
2. 点击托盘图标：
   - 可以恢复显示主窗口。
3. 右击托盘图标：
   - 展示托盘菜单。

托盘菜单建议包含：

1. 打开主窗口。
2. 全局总开关：开启/关闭。
3. 配置列表：
   - 每个配置一个菜单项。
   - 菜单项展示当前开启/关闭状态。
   - 点击后切换该配置状态。
4. 退出程序。

### 5.10 关闭与退出

关闭窗口的行为：

1. 点击关闭按钮时，不隐藏到托盘，而是退出程序。
2. 退出前必须执行统一清理流程：
   - 停止所有配置。
   - 注销所有全局快捷键。
   - 停止所有监听。
   - 取消等待执行的动作。
   - 释放所有可能残留的按键或鼠标状态。
   - 保存最新配置。
3. 托盘菜单点击退出时，也必须执行同一清理流程。
4. 系统退出、应用被要求退出时，也应尽量执行同一清理流程。

### 5.11 配置持久化

配置需要本地保存：

1. 保存位置使用 Tauri 应用数据目录。
2. 建议保存为 JSON 文件。
3. 创建、编辑、删除、启停配置时立即保存。
4. 保存需要使用原子写入策略，避免程序崩溃导致配置文件损坏。
5. 启动时读取配置文件。
6. 配置文件不存在时使用空配置列表。
7. 配置文件损坏时：
   - 不应导致程序崩溃。
   - 需要提示用户配置读取失败。
   - 可备份损坏文件并创建新的空配置。
8. 配置文件不需要在 macOS 和 Windows 之间自动共享。

建议配置结构：

```json
{
  "version": 1,
  "globalEnabled": true,
  "globalToggleHotkey": {
    "keys": ["Option", "Shift", "G"]
  },
  "configs": [
    {
      "id": "uuid",
      "name": "示例配置",
      "enabled": true,
      "triggerHotkey": {
        "keys": ["Option", "A"]
      },
      "toggleHotkey": {
        "keys": ["Option", "Shift", "A"]
      },
      "actions": [
        {
          "type": "keyCombo",
          "keys": ["Command", "A"],
          "delayAfterMs": 100
        },
        {
          "type": "mouseClick",
          "button": "left",
          "clickCount": 1
        }
      ],
      "createdAt": "2026-06-27T00:00:00.000Z",
      "updatedAt": "2026-06-27T00:00:00.000Z"
    }
  ]
}
```

### 5.12 配置导入导出

用户可以手动导入、导出配置。

要求：

1. 导出格式使用 JSON。
2. 导出内容包含 `version`、`globalEnabled`、`globalToggleHotkey` 和 `configs`。
3. 导入时需要校验配置结构和快捷键冲突。
4. 导入时需要支持两种方式：
   - 覆盖当前配置。
   - 追加到当前配置。
5. 追加导入时，如果配置 `id` 冲突，需要为导入项生成新的 `id`。
6. 导入失败时，不应破坏当前已保存配置。
7. 导入、导出只作为手动备份和迁移能力，不要求多设备或跨平台自动同步。

## 8. 技术实现约束

1. 前端使用 React + Ant Design。
2. 桌面容器使用 Tauri。
3. 全局快捷键监听、鼠标键盘模拟应由 Rust 后端负责，前端只负责配置和状态展示。
4. Rust 后端需要向前端提供命令：
   - 读取配置。
   - 保存配置。
   - 创建配置。
   - 更新配置。
   - 删除配置。
   - 设置全局总开关。
   - 设置全局启停快捷键。
   - 设置单个配置启停。
   - 导入配置。
   - 导出配置。
   - 测试注册快捷键。
5. 前端需要监听后端事件：
   - 配置状态变化。
   - 快捷键注册失败。
   - 权限不足。
   - 动作执行失败。
6. 不应在前端浏览器环境中实现全局快捷键监听。
7. 不应把配置保存在 localStorage 作为唯一来源。

## 9. 权限与错误处理

需要覆盖以下错误场景：

1. 缺少系统权限。
2. 快捷键被系统或其他应用占用。
3. 快捷键配置冲突。
4. 配置文件读取失败。
5. 配置文件写入失败。
6. 配置导入失败。
7. 配置导出失败。
8. 动作执行失败。
9. 托盘初始化失败。

错误展示原则：

1. 不使用复杂弹窗打断用户，除非错误会导致核心功能不可用。
2. 配置级错误展示在配置行。
3. 全局错误展示在页面顶部提示条。
4. 权限错误需要提供进入系统设置的说明或入口。

## 10. 验收标准

### 10.1 配置与触发

1. 用户可以新建一个触发快捷键为 `Option + A` 的配置。
2. 用户可以为该配置添加动作：`Command + A`、等待 `100 ms`、鼠标左键单击。
3. 保存后按下 `Option + A`，程序按顺序执行上述动作。
4. 鼠标左键、右键不能被配置为触发项。
5. 用户可以把鼠标点击动作配置为双击。
6. 关闭该配置后，按下触发快捷键不再执行动作。
7. 重新开启该配置后，按下触发快捷键恢复执行动作。

### 10.2 全局控制

1. 全局总开关关闭后，所有配置触发快捷键均不生效。
2. 全局总开关开启后，已启用配置恢复生效。
3. 全局总开关关闭不会把单个配置的启用状态改成关闭。
4. 用户可以配置全局启停快捷键。
5. 按下全局启停快捷键后，全局总开关状态切换。

### 10.3 启停快捷键

1. 用户可以为配置设置启停快捷键。
2. 按下启停快捷键后，该配置在开启和关闭之间切换。
3. 启停快捷键不能与其他配置快捷键冲突。

### 10.4 托盘与退出

1. 点击最小化后，窗口隐藏到托盘，配置继续生效。
2. 托盘右键菜单可以打开主窗口。
3. 托盘右键菜单可以切换全局总开关。
4. 托盘右键菜单可以切换每个配置。
5. 点击窗口关闭按钮后，程序停止所有配置并退出。
6. 托盘菜单点击退出后，程序停止所有配置并退出。

### 10.5 持久化

1. 创建配置后关闭程序，再次打开配置仍存在。
2. 配置启用状态、全局总开关状态再次打开后保持一致。
3. 配置文件损坏时，程序不崩溃，并提示配置读取失败。

### 10.6 Windows 打包

1. 推送 `v*` tag 后触发 Windows 打包 workflow。
2. 手动触发 workflow 可以生成 Windows 安装包。
3. Workflow 成功后可以下载 `.exe` artifact。

### 10.7 导入导出

1. 用户可以导出当前配置为 JSON 文件。
2. 用户可以把导出的 JSON 文件重新导入。
3. 覆盖导入后，当前配置被导入文件替换。
4. 追加导入后，导入配置追加到当前配置列表。
5. 导入失败不会破坏当前配置。

## 12. 已确认项

### 12.1 产品确认项

1. 应用名称：无敌小铃铛。
2. 图标使用 AI 生成的原创图标，当前资产路径为 `assets/app-icon.png`。
3. Bundle Identifier：`com.yuyuehui.mhxykey`。
4. 不需要开机自启动。
5. 鼠标点击只点击当前位置，不需要固定坐标。
6. 本期需要支持鼠标双击。
7. 本期不需要鼠标移动和鼠标滚轮。
8. 全局总开关需要支持配置快捷键。
9. 需要支持配置导入、导出。
10. 不需要跨平台共享同一份配置文件。

### 12.2 明确不支持的动作

以下动作不纳入本期范围：

1. 文本输入：输入一段固定文本。
2. 按键按下、松开、长按：用于需要持续按住某个键的场景。
3. 鼠标按下、松开、长按：用于需要按住鼠标键的场景。
4. 三击：例如鼠标左键三击选中段落。
5. 重复执行：把一段动作序列重复执行指定次数。
6. 剪贴板写入并粘贴：先写入剪贴板，再模拟粘贴。
7. 打开应用或网址：触发后启动本地应用或打开指定 URL。
8. 执行系统命令：触发后运行预设命令，风险较高，默认不建议放入 MVP。
9. 执行完成提示：动作完成后播放提示音或发送系统通知。
